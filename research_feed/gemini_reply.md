### CODE-1｜tools/site_extgap.py:73：前端 JS 一句話生成在首位股票缺漏時出現前置頓號排版瑕疵
- **檔案與行號**：`tools/site_extgap.py` 第 72–73 行
- **那一行在做什麼**：
  ```javascript
  72: var spy=rows.filter(function(x){return x.s==='SPY';})[0],qqq=rows.filter(function(x){return x.s==='QQQ';})[0];
  73: one.textContent='一句話看懂（'+sess+'）：'+(spy?'標普 ETF '+sg(spy.e.chg,2):'')+(qqq?'、那斯達克 ETF '+sg(qqq.e.chg,2):'')+'；'
  ```
- **為什麼有問題**：
  在第 73 行字串拼接中，`qqq` 的文案被寫死為前置帶頓號 `'、那斯達克 ETF '`。當盤前或盤後資料源中因延遲或成交中斷導致 `spy` 不存在（`spy` 為 undefined）而 `qqq` 存在時，該句將被組裝成 `一句話看懂（盤前）：、那斯達克 ETF +0.50%...`，在標點符號後直接緊接頓號，呈現明顯的前端排版與語法瑕疵。
- **建議怎麼改**：
  改採陣列 `filter(Boolean).join('、')` 的健全拼接方式：
  ```javascript
  var leads = [];
  if (spy) leads.push('標普 ETF ' + sg(spy.e.chg, 2));
  if (qqq) leads.push('那斯達克 ETF ' + sg(qqq.e.chg, 2));
  one.textContent = '一句話看懂（' + sess + '）：' + (leads.length ? leads.join('、') : '') + '；'
  ```
- **確定度**：高。

### CODE-2｜tools/site_macro_dash.py:59：五日變化計算條件式語意不一致且存在潛在零值判斷偏誤
- **檔案與行號**：`tools/site_macro_dash.py` 第 56 與 59 行
- **那一行在做什麼**：
  ```python
  56: d1, d5 = (last - prev) * 100, ((last - p5) * 100 if p5 is not None else None)
  ...
  59: d1, d5 = (last / prev - 1) * 100, ((last / p5 - 1) * 100 if p5 else None)
  ```
- **為什麼有問題**：
  在第 56 行（處理點數/利差變化）時，程式正確使用了 `if p5 is not None else None`；但在第 59 行（處理百分比變化）時，卻寫成了 `if p5 else None`。在 Python 中，如果歷史價格序列中某一日剛好出現數值為 `0`（例如期貨合約極端報價或剛上市除權後暫態），`if p5` 會被判斷為 `False` 而錯誤指派 `d5` 為 `None`，而非進行計算或明確防範除以零。此外，第 59 行的 `last / prev - 1` 未事先檢查 `prev` 是否大於 0，一旦資料清洗不全含有 0，將引發運行時 `ZeroDivisionError`。
- **建議怎麼改**：
  統一檢查口徑並防範除以零：
  ```python
  d1 = (last / prev - 1) * 100 if (prev is not None and prev > 0) else None
  d5 = (last / p5 - 1) * 100 if (p5 is not None and p5 > 0) else None
  ```
- **確定度**：中高。

### CODE-3｜wsb/data/china_watch.py:46：三年期平均營收年增計算分母未防範除以零例外
- **檔案與行號**：`wsb/data/china_watch.py` 第 45–46 行
- **那一行在做什麼**：
  ```python
  45: if len(three) == 3 and all(k in series for k in three0):
  46:     out["yoy3"] = sum(series[k] for k in three) / sum(series[k] for k in three0) - 1
  ```
- **為什麼有問題**：
  在第 46 行中，直接將去年同期 3 個月的總和 `sum(series[k] for k in three0)` 作為除數。如果歷史數據在 OECD 資料庫中存在數據缺損填補為 0，或歷史基期合計為 0，將直接在運行時拋出 `ZeroDivisionError`，導致整個經濟卡快取更新中斷。
- **建議怎麼改**：
  增加分母有效性保護：
  ```python
  denom = sum(series[k] for k in three0)
  if denom:
      out["yoy3"] = sum(series[k] for k in three) / denom - 1
  ```
- **確定度**：高。
