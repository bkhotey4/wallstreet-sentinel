### CODE-1｜tools/site_fedspeech.py:70：歷史日線序列存在重複日期時 get_loc 回傳 slice 導致比較運算拋出 TypeError
- **檔案與行號**：`tools/site_fedspeech.py` 第 70–71 行
- **那一行在做什麼**：
  ```python
  70: i = s.index.get_loc(day)
  71: if i < 61:
  72:     return None
  ```
- **為什麼有問題**：
  在 Pandas 中，若 `s.index`（經過 `with_treasury` 合併或 FRED 原始資料存在異常重複日期戳記）包含多個相同的 `day`，`s.index.get_loc(day)` 將回傳一個 `slice` 物件或布林遮罩陣列，而不是單一整數（`int`）。執行第 71 行 `if i < 61:` 時，Python 將直接拋出 `TypeError: '<' not supported between instances of 'slice' and 'int'`，中斷整張聯準會官員演說卡片的渲染流程。
- **建議怎麼改**：
  在取位置前確保索引唯一，或轉換為整數下標：
  ```python
  loc = s.index.get_loc(day)
  i = loc.start if isinstance(loc, slice) else (loc[0] if hasattr(loc, '__iter__') else loc)
  if i < 61:
      return None
  ```
- **確定度**：高。

### CODE-2｜tools/site_twpaper.py:21：上櫃股票代號清洗僅移除 .TW 漏除 .TWO 後綴
- **檔案與行號**：`tools/site_twpaper.py` 第 20–21 行
- **那一行在做什麼**：
  ```python
  20: def _nm(r: Dict) -> str:
  21:     return esc(f'{r["sym"].replace(".TW", "")} {r.get("name") or ""}'.strip())
  ```
- **為什麼有問題**：
  在台灣股市資料源中，上市股票後綴為 `.TW`，上櫃（OTC）股票後綴為 `.TWO`。第 21 行只執行了 `.replace(".TW", "")`，當規則池選入上櫃股票（例如 6488 環球晶、3131 弘塑）時，代號會被顯示成 `6488.TWO 環球晶`，未能徹底剝除 Yahoo 行情代碼後綴，造成表格排版長度暴衝與字樣不一致。
- **建議怎麼改**：
  統一替換上市與上櫃後綴：
  ```python
  clean_sym = r["sym"].replace(".TWO", "").replace(".TW", "")
  return esc(f'{clean_sym} {r.get("name") or ""}'.strip())
  ```
- **確定度**：高。

### CODE-3｜wsb/data/country_risk.py:79：匯率極端值計算在無有效平滑數值時 max() 引發 ValueError
- **檔案與行號**：`wsb/data/country_risk.py` 第 78–79 行
- **那一行在做什麼**：
  ```python
  78: val = lambda old: (old / now - 1) * 100 if old else None
  79: top = max(x for x in (smooth(c, b) for b in range(0, len(c) - 5, 5)) if x)
  ```
- **為什麼有問題**：
  生成器表達式 `(x for x in ... if x)` 若因 Yahoo 匯率抓取異常、歷史資料缺漏或非交易日填補為空，導致所有 `smooth(c, b)` 回傳皆為 `None`，生成器將產出空序列。此時 Python 的 `max()` 函式未指定 `default` 參數，將直接拋出運行時例外：`ValueError: max() arg is an empty sequence`，導致各國危機雷達的快取建置失敗中斷。
- **建議怎麼改**：
  為 `max()` 提供預設值保護：
  ```python
  top = max((x for x in (smooth(c, b) for b in range(0, len(c) - 5, 5)) if x), default=None)
  ```
- **確定度**：高。

### CODE-4｜functions/api/quote.js:39：RSI 在平盤無波動時零除零錯誤回傳 100 極端超買假象
- **檔案與行號**：`functions/api/quote.js` 第 38–39 行
- **那一行在做什麼**：
  ```javascript
  38:   }
  39:   return dn === 0 ? 100 : 100 - 100 / (1 + up / dn);
  40: }
  ```
- **為什麼有問題**：
  當某檔股票在過去 14 天內處於停牌、流動性凍結或每日價格完全無波動（`d === 0`）時，上漲累積 `up === 0` 且下跌累積 `dn === 0`。第 39 行的三元運算子僅檢查 `dn === 0` 便直接回傳 `100`。這會讓完全沒有交易波動的平盤標的在前端體檢表中被錯誤標記為「RSI = 100（極度超買過熱）」，產生嚴重的指標誤導。
- **建議怎麼改**：
  先判定兩者皆為 0 時的中性水準：
  ```javascript
  if (up === 0 && dn === 0) return 50;
  return dn === 0 ? 100 : 100 - 100 / (1 + up / dn);
  ```
- **確定度**：高。
