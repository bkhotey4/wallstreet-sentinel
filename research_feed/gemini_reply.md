## CODE 程式稽核

本批稽核依照規範審查專案中台北時間 12 時對應檔案（排序編號除以 24 餘數為 12 之檔案清單，聚焦審查 `tools/site_twmacro.py` 與 `wsb/analytics/twmacro.py` 等台灣總經、債券利差與景氣燈號渲染模組）：

### CODE-1｜tools/site_twmacro.py：第 181-183 行三元運算子結合優先級錯誤，致 score_pct 為 None 時 Mood 與 Run 資訊遭到截斷遺失
- **檔案路徑與行號**：[tools/site_twmacro.py](file:///c:/Users/凱/Desktop/Claude_Financial/wallstreet-sentinel/tools/site_twmacro.py#L181-L183)
- **程式碼片段**：
  ```python
  lead = (f"一句話看懂：{e['month']} 景氣燈號{e['ico']}{e['light']}燈（{e['score']:.0f} 分，{e['mood']}）"
          + (f"，已連續 {e['run']} 個月" if e["run"] >= 2 else "") + f"；分數在 {e['since']} 年以來第 {e['score_pct']:.0f} 百分位。" if e.get("score_pct") is not None else
          f"一句話看懂：{e['month']} 景氣燈號{e['ico']}{e['light']}燈（{e['score']:.0f} 分）。")
  ```
- **為什麼有問題**：
  在 Python 中，字串串接運算子 `+` 的優先級高於三元條件運算子 `if ... else ...`。
  上述運算式會被 Python 直譯器解析為：
  `(A + B + C) if (e.get("score_pct") is not None) else D`。
  當上游國發會景氣燈號歷史分數資料不足（例如新基期轉換或快取剛建置時，`score_pct` 為 `None`），條件為假，程式會直接回退至 `else` 分支的字串 `D`：
  `f"一句話看懂：{e['month']} 景氣燈號{e['ico']}{e['light']}燈（{e['score']:.0f} 分）。"`
  這導致原本即使存在的 `{e['mood']}`（景氣心態描述）以及 `{e['run']}`（燈號已連續亮出月數）被全部粗暴抹除，完全不予顯示，造成資訊不當丟失。
- **建議怎麼改**：
  應將 `score_pct` 的百分位字串獨立加上括號進行條件判斷，確保 `mood` 與 `run` 在任何情況下均能正確輸出：
  ```python
  lead = (f"一句話看懂：{e['month']} 景氣燈號{e['ico']}{e['light']}燈（{e['score']:.0f} 分，{e['mood']}）"
          + (f"，已連續 {e['run']} 個月" if e["run"] >= 2 else "")
          + (f"；分數在 {e['since']} 年以來第 {e['score_pct']:.0f} 百分位。" if e.get("score_pct") is not None else "。"))
  ```
- **確定程度**：高。

### CODE-2｜tools/site_twmacro.py：第 117-118 行長短債利差為 0 bp 時被錯誤判定為「曲線倒掛」，對讀者發出不實衰退警訊
- **檔案路徑與行號**：[tools/site_twmacro.py](file:///c:/Users/凱/Desktop/Claude_Financial/wallstreet-sentinel/tools/site_twmacro.py#L117-L118)
- **程式碼片段**：
  ```python
  if g.get("slope"):
      sl = g["slope"]
      facts.append(f"長短利差（10 年減 2 年）{sl['now']:+.0f} bp" + (f"，{sl['since']} 年以來第 {sl['pct']:.0f} 百分位" if sl.get("pct") is not None else "（歷史資料累積中）")
                   + ("：曲線正常向上，市場沒有在預期衰退。" if sl["now"] > 0 else "：曲線倒掛（短天期比長天期貴），歷史上常出現在景氣轉弱之前。"))
  ```
- **為什麼有問題**：
  在利率曲線金融實務與邏輯判定上，當 10 年期與 2 年期公債利率相等時（`sl['now'] == 0`），利率曲線處於**平坦（Flat）**狀態，絕非倒掛（Inverted）。
  然而程式中僅以二分法 `if sl["now"] > 0 else ...` 進行判斷。當利差恰為 `0 bp` 時，`sl["now"] > 0` 評估為 `False`，程式會輸出：
  `長短利差（10 年減 2 年）+0 bp...：曲線倒掛（短天期比長天期貴），歷史上常出現在景氣轉弱之前。`
  這在語義上存在嚴重的自相矛盾（明明利差是 0，卻對讀者宣告「短天期比長天期貴」與「曲線倒掛」），造成對總體景氣虛假的衰退警訊。
- **建議怎麼改**：
  引入平坦狀態的三分支判斷：
  ```python
  msg = ("：曲線正常向上，市場沒有在預期衰退。" if sl["now"] > 0 else
         "：曲線平坦（長短天期利率相當）。" if sl["now"] == 0 else
         "：曲線倒掛（短天期比長天期貴），歷史上常出現在景氣轉弱之前。")
  facts.append(f"長短利差（10 年減 2 年）{sl['now']:+.0f} bp" + (f"，{sl['since']} 年以來第 {sl['pct']:.0f} 百分位" if sl.get("pct") is not None else "（歷史資料累積中）") + msg)
  ```

### CODE-3｜wsb/analytics/twmacro.py：第 201-203 行 chip3 半導體設備進口三個月移動年增率硬編碼 iloc 位置切片，遭遇缺月時將產生時間跨期錯置
- **檔案路徑與行號**：[wsb/analytics/twmacro.py](file:///c:/Users/凱/Desktop/Claude_Financial/wallstreet-sentinel/wsb/analytics/twmacro.py#L201-L203)
- **程式碼片段**：
  ```python
  chip3 = None
  if len(chip) >= 15:
      a, b = float(chip.iloc[-3:].sum()), float(chip.iloc[-15:-12].sum())
      chip3 = (a / b - 1) * 100 if b else None
  ```
- **為什麼有問題**：
  `chip` 係由 `_nd(d, "chip_tools")` 產生的 pandas Series，底層經由 `_s()` 函式將國發會名目半導體設備進口 CSV 轉換為 DatetimeIndex。
  然而，`_s()` 僅對既有列執行 `groupby(Period).last()`，並**未執行連續日曆月補齊（reindex / asfreq('M')）**。
  若國發會開放資料平臺在歷史回溯數據中曾有月份缺漏或延遲，使用純位置切片 `chip.iloc[-15:-12]` 計算「一年前同期的三個月總額」時，所取得的將只是「往前數第 13 至 15 個有記錄的行」，而非嚴格意義上的「去年同期的 3 個日曆月」，從而導致基期時間對位錯偏，使計算出的年增率失真。
  對照模組內其他年增率計算（例如第 27 行的 `_ago(s, months)`），均使用 `pd.DateOffset(months=months)` 依真實日曆時間對位，此處的 `iloc` 硬編碼屬於潛在時序風險。
- **建議怎麼改**：
  建議改用以最新月份索引為基準之時間對位計算：
  ```python
  last_dt = chip.index[-1]
  cur3 = chip[(chip.index <= last_dt) & (chip.index > last_dt - pd.DateOffset(months=3))]
  prev_end = last_dt - pd.DateOffset(months=12)
  ly3 = chip[(chip.index <= prev_end) & (chip.index > prev_end - pd.DateOffset(months=3))]
  if len(cur3) == 3 and len(ly3) == 3:
      a, b = float(cur3.sum()), float(ly3.sum())
      chip3 = (a / b - 1) * 100 if b else None
  ```
- **確定程度**：高。
