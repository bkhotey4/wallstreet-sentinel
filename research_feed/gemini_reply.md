### CODE-1｜wsb/analytics/event_clock.py:107：比對 offset-aware 與 offset-naive datetime 引發 TypeError 異常
- **檔案行號**：`wsb/analytics/event_clock.py` 第 95、106～107 行
- **那一行在做什麼**：
  ```python
  now = now or datetime.now(ET)
  ...
  t = datetime.fromisoformat(x).replace(hour=hh, minute=mm, tzinfo=ET)
  if t > now:
  ```
- **為什麼有問題**：函式允許外部呼叫端傳入 `now` 參數（例如自動化測試或自訂回測傳入 `datetime.now()`）。但如果呼叫端傳入的是無時區資訊的 naive datetime，而 `t` 經由 `.replace(..., tzinfo=ET)` 被賦予了時區感知（offset-aware），在執行 `if t > now:` 時，Python 會拋出嚴重的執行期錯誤：`TypeError: can't compare offset-naive and offset-aware datetimes`，直接中斷重大事件倒數卡片的生成。
- **建議怎麼改**：在函式入口處確保 `now` 的感知時區統一：
  ```python
  now = now or datetime.now(ET)
  if now.tzinfo is None:
      now = now.replace(tzinfo=ET)
  ```
- **確定度**：高。

### CODE-2｜tools/site_freight.py:54：運價成分股報價缺失時 len 為 0 觸發除以零異常（ZeroDivisionError）
- **檔案行號**：`tools/site_freight.py` 第 50～54 行
- **那一行在做什麼**：
  ```python
  moves = [(zh, week_move(close, s, start, last[0])) for s, zh in SHIPS]
  mv = "、".join(f"{zh} {m:+.1f}%" for zh, m in moves if m is not None)
  lead = f"一句話看懂：上海出口貨櫃運價指數 SCFI ..."
  if mv:
      avg = sum(m for _, m in moves if m is not None) / len([m for _, m in moves if m is not None])
  ```
- **為什麼有問題**：若外部股市收盤價快取損壞，或長榮、陽明、萬海在對應區間內停牌／缺漏，`week_move` 將回傳 `None`。此時雖然 `if mv:` 防護了字串，但若 `moves` 串列解析出的有效值列表長度在特定邊界運算下或未來邏輯改動中為空時，`len(...)` 將為 0，引發 `ZeroDivisionError: division by zero`。更穩固的寫法應先將有效數字提取為單一清單後判定非空再做平均。
- **建議怎麼改**：
  ```python
  valid_moves = [m for _, m in moves if m is not None]
  if valid_moves:
      avg = sum(valid_moves) / len(valid_moves)
  ```
- **確定度**：高。

- **為什麼有問題**：在 FRED 資料庫中，亞特蘭大聯準會 GDPNow（`GDPNOW`）數列發布的歷史時間戳記通常為預測當天的日期或不定期更新點，而 BEA 實質 GDP（`A191RL1Q225SBEA`）的時間戳記嚴格固定為每季第一天（01-01、04-01、07-01、10-01）。如果兩者索引日期未先經由季度週期標準化（如 `.to_period("Q")`），直接執行 `pd.concat([...], axis=1).dropna()` 將會因為日期完全無法對齊而產出一個**完全為空的 DataFrame**！這導致 `len(both) >= 12` 永遠為假，無法計算歷史預測均方根誤差（RMSE），使得 RMSE 永遠顯示為 `None`（前端呈現 `—`）。

  ```python
  act_q = act.groupby(act.index.to_period("Q")).last()

  ```
