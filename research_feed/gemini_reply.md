#### SITE-1 正則表達式與動態頁面更新邏輯審查（針對 `tools/site_layout.py:99`）
- **問題分析**：在 `tools/site_layout.py` 中解析國發會新聞稿標題時，原先的正則表達式設計預設格式為固定月份前綴。然而國發會發布 10 月景氣概況時，官方標題常伴隨「115年10月景氣對策信號...」或「2026年10月景氣對策信號...」之年份切換。若正則匹配式僅抓取 `(\d{1,2})月景氣燈號`，容易遺漏年份資訊，導致回溯歷史檔案時產生月份覆蓋錯誤。
- **代碼改進建議**：
  ```python
  # 建議在 tools/site_layout.py 或 site_econ.py 中強化正則匹配容錯度：
  import re
  pattern = re.compile(r'(?:(?:11[4-6]|202[5-7])\s*年\s*)?(\d{1,2})\s*月\s*景氣(?:對策)?(?:信號|燈號)', re.IGNORECASE)
  match = pattern.search(title_text)
  if match:
      month = int(match.group(1))
  ```

### CODE. 程式碼審查與系統優化（Batch 8）

#### 審查對象：`tools/site_corpfund.py` 與 `tools/site_events.py`
- **代碼隱患 1：`tools/site_corpfund.py:78` 潛在 `ValueError: max() arg is an empty sequence`**
  - **代碼行**：`mx = max(tot.values()) or 1.0`
  - **問題剖析**：若當日法人買賣超數據因國定假日或網路抓取異常而導致 `tot` 字典為空 `{}` 時，`tot.values()` 將為空序列，直接調用 `max()` 會拋出 `ValueError` 例外中斷整個生成流程。
  - **防禦性重構建議**：
    ```python
    # 建議修正為安全取值方式：
    mx = max(tot.values(), default=1.0)
    if mx == 0:
        mx = 1.0
    ```
- **代碼隱患 2：`tools/site_events.py:194` 跨時區事件比較的時間戳不一致**
  - **代碼行**：`if now < t <= now + timedelta(days=days):`
  - **問題剖析**：美股財報事件通常標註為美東時間（EST/EDT），而系統 `now` 在本機執行時若採用台北時間（UTC+8），直接進行浮點數或無時區（naive datetime）比較會產生 13 小時的時差偏差，導致剛好在邊界的事件被提早或延遲過濾。
  - **防禦性重構建議**：應統一將事件時間戳與當前時間轉換為 UTC 或標註明確之時區感知（timezone-aware）對象後再行比較。
